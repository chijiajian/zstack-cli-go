# 4.4: 提供显式加载的 PowerCLI 风格子集

**Story ID:** 4.4
**Epic:** 4 — 启动与兼容入口
**Slug:** compatibility-module
**Status:** review

> 单次开发会话范围（约2–8小时）；本文件仅规划。前置依赖完成后实施，不包含真实云操作或发布。

## Story

As a **保留旧命令名称的迁移客户**, I want **在独立会话中加载有限同名命令入口**, so that **减少已覆盖脚本的命令改名并清楚识别不兼容内容**。

## Acceptance Criteria

<!-- LOCKED：外部开发工具不得修改。 -->

1. 给定无冲突的独立 pwsh 会话，当显式加载兼容模块时，则仅导出 Connect-VIServer、Disconnect-VIServer、Get-VM、Start-VM 约定子集，委托同一中性核心，不复制认证/查询/写逻辑；主模块默认不导出这些名字。
2. 给定 VMware、Hyper-V 或用户函数已提供任一冲突名称，当导入兼容模块时，则使用 Get-Command -All 检测后拒绝并给出独立会话提示；不强制覆盖、不改变 DefaultVIServer/全局别名，卸载无全局残留。
3. 给定兼容清单中的 -Server/-Credential、查询 Name/Id、启动 VM 对象或名称数组以及 CommonParameters，当执行时，则按已定义原生语义委托；对不支持参数、Vmware类型或模块限定调用要求明确标出差异，不悄悄丢弃输入。
4. 给定至少查询、管道、启动、冲突四类合成脚本，当评估时，则记录保留部分与必要改动；不得将这些结果称为全量PowerCLI或客户真实脚本认证。

FR-006 / NFR-006；[Source: prd.md#fr-006] [Source: architecture.md#adr-006-naming--oem--compatibility-are-independent]。Cloud.PowerCLI.Compatibility 是内部拟议包源文件名，不是已批准公开发行名。参数白名单受1.1基线约束：连接Server/Credential；断开Server；查询Name/Id/Server；启动VM/Server和CommonParameters。Native的Name/Id启动入口不隐式扩展兼容参数集。Get-View、ExtensionData、RunAsync、Kill未支持。

## Testing

<!-- LOCKED：测试策略，本轮不执行。 -->

**Approach:** 开发阶段采用 Pester 单元或本地集成测试，CLI/云调用使用合成 stub；不包含真实凭据。

- AC #1 → 用命令发现验证默认/兼容包导出集合并检查委托路径。
- AC #2 → 用同名stub与真实安装可选场景验证冲突前后函数/变量保持不变。
- AC #3 → 参数表驱动验证所有允许与拒绝输入，不支持项0云调用。
- AC #4 → 四类合成脚本保存分类结果，标记synthetic且不引入真实数据。

**Fixtures / mocks:** 本故事 Owned Scope 下的合成资源与stub，复用已有process/registry测试工具；不保存敏感服务端响应。
**Downstream checks:** 按仓库AGENTS.md运行适当模块回归与make verify；如实际改变CLI命令，补生成参考与Skill检查。真实环境验证另行授权。
