# 4.3: 提供状态等待与可诊断超时

**Story ID:** 4.3
**Epic:** 4 — 启动与兼容入口
**Slug:** wait-vm
**Status:** review

> 单次开发会话范围（约2–8小时）；本文件仅规划。前置依赖完成后实施，不包含真实云操作或发布。

## Story

As a **自动化脚本作者**, I want **等待指定 VM 达到 Running 并设置截止时间**, so that **避免将请求返回误判为操作完成**。

## Acceptance Criteria

<!-- LOCKED：外部开发工具不得修改。 -->

1. 给定有效 VM 对象，当调用拟议 Wait-<Prefix>VM -State Running 时，则使用所属连接的 CLI wait instance，只查询不启动，达到 Running 后返回刷新投影 VM。
2. 给定 TimeoutSeconds/PollSeconds，当参数省略时使用300/2秒，允许范围分别为1–3600/1–60；非法值本地拒绝。供 Start 内部复用时接受剩余 deadline，不能重置启动总超时。
3. 给定一直未到目标状态、取消、连接失效或 CLI 错误，当等待结束时，则产生可区分的超时/取消/连接/远端错误，不宣称目标已达成或服务器回滚；不重试任何写。由 Start 调用的等待失败由 Start 标记未知最终写结果。

## Dev Notes

<!-- LOCKED：带来源的实施契约。 -->

FR-005 / NFR-002；[Source: prd.md#fr-005] [Source: architecture.md#api-contract]。此处 Wait 不是 VMware Wait-Task，只支持本次 Running 状态契约。公共等待和启动共用一个私有 helper；状态轮询复用 CLI wait，不另写SDK调用。wait成功的JSON是Observation，不是完整VM；在同一剩余deadline内按UUID调用get instances -o json重新读取并投影，身份/状态再次不符则报状态变化错误，不返回旧的假成功对象。取消子进程不保证取消已在云端执行的动作。[Source: architecture.md#adr-005-errorresponse-and-mutation-conventions]

范围只包含 Owned Scope；公开函数导出通过2.1装载契约与5.2生成清单接入，不修改其他故事的bootstrap。命令前缀由品牌配置生成，不写死 ZStack。使用现有适配器/registry/错误转换，不重复传输或锁逻辑。[Source: architecture.md#component-design]
