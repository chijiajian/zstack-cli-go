# 3.2: 提供分页与名称筛选的原生查询

**Story ID:** 3.2
**Epic:** 3 — VM 查询与对象
**Slug:** vm-query
**Status:** done

> 单次开发会话范围（约2–8小时）；本文件仅规划。前置依赖完成后实施，不包含真实云操作或发布。

## Story

As a **运维脚本作者**, I want **用熟悉的 Get 命令查询全部或指定 VM**, so that **不必自己拼接 CLI 和解析 JSON**。

## Acceptance Criteria

<!-- LOCKED：外部开发工具不得修改。 -->

1. 给定一个有效连接，当调用拟议 Get-<Prefix>VM 而不传 Name/Id 时，则经包内 CLI get instances --all-pages --sort +uuid -o json 取得所有页并输出 VM 对象；不得逐 VM 调用 describe。
2. 给定 -Name string[] 或位置0名称参数，当含精确名称、星号或问号通配符时，则在完整分页结果上按 PowerShell WildcardPattern IgnoreCase 筛选；-Id string[] 按精确 UUID 筛选，Name/Id 同传、空数组或空字符串在云查询前报绑定错误。
3. 给定零/一/多结果、中文名称和分布在不同页的匹配，当查询时，则无匹配产生零个成功流对象，其余逐对象输出；显式 -Server 路由正确，多连接未指定 Server 时拒绝，不修改 CLI 默认 context。
4. 给定 10000 台合成 VM，当运行查询基准时，则记录首项/总耗时、峰值内存及进程/API 调用数量，证明无逐 VM describe；NFR-003 的性能目标与实测偏差分别报告。

## Testing

<!-- LOCKED：测试策略，本轮不执行。 -->

**Approach:** 开发阶段采用 Pester 单元或本地集成测试，CLI/云调用使用合成 stub；不包含真实凭据。

- AC #1 → 用 CLI stub 核对 all-pages、sort、JSON 与调用数量。
- AC #2 → 用参数化表核对通配符、大小写、互斥和空值拒绝。
- AC #3 → 模拟跨页、空集、单项、多连接并断言成功流仅对象。
- AC #4 → 固定基准机器及20次预热样本记录差值，不把目标当结果。

**Fixtures / mocks:** 本故事 Owned Scope 下的合成资源与stub，复用已有process/registry测试工具；不保存敏感服务端响应。
**Downstream checks:** 按仓库AGENTS.md运行适当模块回归与make verify；如实际改变CLI命令，补生成参考与Skill检查。真实环境验证另行授权。
