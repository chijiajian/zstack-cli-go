# 3.4: 验证并完成查询对象的 PowerShell 管道体验

**Story ID:** 3.4
**Epic:** 3 — VM 查询与对象
**Slug:** query-pipeline
**Status:** review

> 单次开发会话范围（约2–8小时）；本文件仅规划。前置依赖完成后实施，不包含真实云操作或发布。

## Story

As a **已有 PowerCLI 报表的客户**, I want **继续使用 Where-Object、Select-Object 与 Export-Csv**, so that **仅更换连接与查询入口而保留报表处理段**。

## Acceptance Criteria

<!-- LOCKED：外部开发工具不得修改。 -->

1. 给定合成迁移报表，当把 Get-VM 查询入口替换为已生成的品牌查询命令时，则原有 Where-Object PowerState、Select-Object Name/NumCpu/MemoryGB 与 Export-Csv 段保持不变并产生正确结果。
2. 给定查询返回零、一、多台 VM，当经过 ForEach-Object 和 Select-Object 管道时，则数量和属性类型正确；成功流无标题、JSON文本、诊断或进度信息，中文内容导出 UTF-8。
3. 给定有效显式 -Server 与默认连接变化，当查询对象进入后续资源选择器时，则对象仍绑定原连接；配置或错误信息不混入 CSV，查询失败按既定 ErrorRecord 契约处理。

## Tasks / Subtasks

- [ ] 完成报表管道回归及所需查询输出修正 (AC: #1)
- [ ] 验证数组枚举、成功流纯净与编码 (AC: #2)
- [ ] 验证管道中连接身份和错误流 (AC: #3)
