# 1.3: 让启动命令提供可靠机器输出

**Story ID:** 1.3
**Epic:** 1
**Slug:** start-json-contract
**Status:** done

> 一个开发会话（约2–8小时）目标；若实作发现超过一天，先在规划中拆分，不扩大契约。

## Story

作为 **模块维护者**，我希望 **消费完整JSON启动结果**，从而 **不解析进度文本或漏掉部分失败**。

## Acceptance Criteria

<!-- LOCKED: 未经明确规划更新，不修改验收契约。 -->

1. 给定 instance start UUID --yes -o json，stdout只有一个operation/items envelope；成功、失败、skipped均有uuid/status；提示/进度不得混入stdout。
2. 给定部分失败，仍输出可解析结果并返回非零；error-format json的诊断遵循现有脱敏错误约定；默认text保持相邻命令风格。
3. 给定 dry-run 或无可启动资源，JSON仍符合相同envelope；不会把skipped当作成功；保持原CLI名称批量行为，模块另行只传UUID。

## Tasks / Subtasks

- [ ] 为start JSON模式分离提示与结果 (AC: #1)
- [ ] 输出部分失败机器项并保留text模式 (AC: #2)
- [ ] 统一dry-run与skipped结果契约 (AC: #3)
