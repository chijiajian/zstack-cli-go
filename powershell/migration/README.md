# PowerCLI migration cases

The corpus contains 12 baseline pairs and eight original pairs adapted from public workflows. The public cases include source links, stable scenario IDs, reusable pipelines, and VMware-specific behavior that requires changes. The snippets are data and depend on the connection and resource selections shown in the [examples](../../examples/powershell/README.md#public-powercli-scenarios).

Run `Assess-Migration.ps1 -ContractReport <loopback report>` to associate each case with its behavior check. `unchanged` retains the snippet with ZStack connection and resource values. `command-only` retains the pipeline after command substitutions. `rewrite` requires data, parameters or workflow changes. `review` requires checking environment-dependent behavior. `Passed` describes the associated synthetic behavior checks. Use separate evidence for Windows cloud runs and customer scripts.

For customer intake, ask for sanitized scripts and record the source module version, commands, bound parameters, pipeline input and output properties. Flag module-qualified calls, dynamically constructed commands, VMware types, `Get-View`, `.ExtensionData`, and asynchronous tasks for manual review. Keep customer scripts out of the repository unless their owner authorizes sharing.

The report contains `Summary` and `Cases`. `InScopePassRate` divides recorded passes by the supported samples selected for the run that can be assessed automatically. `SkippedCases` lists cases excluded by the report scope. `UnrecordedCases` lists cases whose checks have no evidence in the report. An unrecorded case that qualifies for automatic assessment stays in the denominator. The line counts compare the snippets in order and report inserted and deleted lines. A line replacement contributes one insertion and one deletion. Command replacements use the PowerShell parser to count the named substitutions declared in each pair. Newly added or removed commands are separate from replacements.

Save the report as `$assessment` and use `$assessment.Cases | Where-Object Group -eq 'public'` to inspect the public scenario set. S01–S03 preserve their snippet. S04–S07 document workflow rewrites. S08 records the gap for per-VM historical metrics and VMware API objects. A report from `-ZStackOnly` lists `oem-native` under `SkippedCases` and retains the recorded compatibility collision check. Earlier reports without a scope marker use the full corpus.
